# Running SynapseNet locally

This guide starts the runnable SynapseNet MVP: a one-orderer, one-peer Hyperledger
Fabric network backed by CouchDB, the credential chaincode, and its Node.js
gateway and browser console.

## Prerequisites

- Docker Engine or Docker Desktop with Linux containers
- Docker Compose v2 (`docker compose`) or legacy `docker-compose`
- Node.js 20
- Yarn 1.x
- Bash (WSL2 is recommended on Windows)

On Windows, keep the repository in the WSL filesystem (for example,
`~/projects/SynapseNet`) for better Docker and Node filesystem performance.

## First run

From the repository root:

```bash
cp .env.example .env
yarn install --frozen-lockfile
yarn chaincode:test
yarn network:up
yarn network:create-channel
yarn network:deploy
yarn network:test
```

`network:up` automatically generates local development certificates and channel
artifacts when they are missing. The generated files contain private keys and are
ignored by Git.

The chaincode runs as a containerized external service (Fabric
Chaincode-as-a-Service). This is compatible with Docker Engine 29 and avoids the
legacy peer-side Docker builder.

The smoke test onboards a user and enterprise, submits and approves an
evidence-backed credential, and verifies that it appears in the user's wallet.

## Start the test UI

Keep the Fabric network running, then start the local gateway and browser UI:

```bash
yarn ui:start
```

Open <http://localhost:3001>. This is the only browser entry point: it displays
the public landing page while signed out and the application after successful
sign-in. Register and sign in as either a user or enterprise reviewer. The UI provides role-specific onboarding, bespoke credential forms,
enterprise validation, user and enterprise credential wallets, dummy SNT token
balances, and recipient-authenticated selective QR sharing. Stop the UI with
`Ctrl+C`; this does not stop Fabric.

Project and API documentation is served by the application API with one shared
navigation bar, Roboto typography, color palette, and responsive layout:

- Project documents: <http://localhost:8000/docs>
- Swagger API: <http://localhost:8000/api/docs>
- ReDoc API: <http://localhost:8000/api/redoc>

The landing-page **Explore the platform** link opens the project documentation
in a new browser tab.

To activate a ledger identity that reports `Login not configured`, or reset an
existing password, issue a one-time token and enter it in the reset form:

```bash
yarn users:list
yarn auth:issue-reset <login-id>
```

Tokens expire after 30 minutes and are invalidated after first use. For stable
sessions, set `SESSION_SECRET` to a strong environment-specific secret before
starting the UI.

In local development, users can instead expand the password activation/reset
form, enter their login ID, and select **Get one-time token**. The generated
token is filled in automatically. This convenience endpoint is disabled when
`NODE_ENV=production`.

After upgrading an older ledger to wallet-enabled chaincode, initialize wallets
for all existing users and enterprises:

```bash
yarn wallets:initialize
```

If certificates were generated by an older version of the scripts and the UI
reports `EACCES` for `priv_sk`, regenerate them using the clean-start procedure
in Troubleshooting.

## Day-to-day commands

```bash
# Show container state
docker compose ps

# Follow Fabric logs
docker compose logs -f orderer.synapsenet.com peer0.org1.synapsenet.com

# Stop containers but retain the ledger
yarn network:down

# Remove containers and ledger volumes
yarn network:reset
```

After changing chaincode, increase `CHAINCODE_SEQUENCE` and optionally
`CHAINCODE_VERSION` for the deployment:

```bash
CHAINCODE_SEQUENCE=2 CHAINCODE_VERSION=1.1 yarn network:deploy
```

## Query the chaincode manually

```bash
docker compose exec cli peer chaincode query \
  -C synapsenet \
  -n skill-manager \
  -c '{"function":"getCredentialRequests","Args":[]}'
```

Use `yarn network:test` for a complete command-line transaction example.

## Troubleshooting

If Docker reports missing bind-mounted certificate files, regenerate the network:

```bash
yarn network:reset
rm -rf blockchain/network/crypto-config blockchain/network/channel-artifacts
yarn network:up
```

The removal command above deletes generated local development identities. Do not
use it for production credentials.

If chaincode deployment says the sequence is already defined, increment
`CHAINCODE_SEQUENCE`. If a container is unhealthy, inspect its logs with:

```bash
docker compose ps
docker compose logs --tail=200
```

## Production hardening still required

The local gateway uses one Org1 admin certificate and logical actor IDs. A
production deployment must enroll users and enterprise reviewers separately,
bind authorization to certificate attributes or enterprise MSPs, keep storage
references encrypted off-ledger, authenticate QR recipients, and add durable
off-chain access/audit services.
